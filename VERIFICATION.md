# Проверка 1.4.2 — совместимость с Chrome 138

5 октября 2026: вызов `chrome.storage.local.setAccessLevel` выполняется только при наличии метода. На Chrome 138 его отсутствие больше не прерывает инициализацию. Ограничения для session сохраняются; на новых браузерах вызываются оба метода. Ошибки существующего метода не подавляются.

16 Node.js-тестов прошли. Два новых теста сначала воспроизвели исходный TypeError, затем прошли после исправления: восстановление подписки и правил с сохранением ограничений session; восстановление блокирующего прокси при включённом VPN и явное отключение. Дополнительно проверен вызов обоих методов на поддерживающем их браузере. API Chrome в тестах имитируется; реальный Chrome 138 на сервере пользователя не запускался.

Готовый комплект 1.4.2 переупакован из проверенного архива 1.4.1 с обновлением расширения и README. До переупаковки проверены SHA-256 архива и каждого файла; помощник и ядро не изменены. `tests/package_smoke.py` подтвердил CRC, контрольные суммы нового комплекта, Install.ps1 -VerifyOnly, отказ повреждённому комплекту, запуск EXE, Native Messaging и проверку origin. Проверка синтаксиса background.js и git diff --check прошла.

## Проверка 1.4.0 — новый интерфейс расширения

Дата: 29 сентября 2026. Windows x64, Chrome, Python 3.14, Node.js 25, sing-box 1.14.1.

## Проверено

- Утверждённый макет перенесён в рабочий popup 400 × 600. Вкладки VPN, Правила и Настройки, выбор сервера и редактор правила работают в одном окне. Демонстрационные серверы и команды удалены. Скрипт вынесен в отдельный файл для Manifest V3.
- 47 Python-тестов прошли, включая настоящий локальный Hysteria 2-сервер, правила доменов/IP, порядок маршрутов, отсутствие прямого обхода VPN, Native Messaging и обновления. Первый запуск в песочнице не смог работать с временными каталогами Windows; повтор вне песочницы прошёл полностью.
- 13 Node.js-тестов фонового worker прошли: сохранение маршрутов, блокировка трафика при потере помощника, восстановление состояния и проверки завершения обновления.
- `tests/routing_ui_smoke.py` проверил рабочие HTML/CSS/JS в отдельном headless Chrome с имитацией RPC: загрузку серверов, выбор по индексу, обновление выбранного сервера при неизменном списке, подключение/отключение, отключение из заблокированного состояния, белую иконку питания, запреты при активном VPN, добавление/перестановку/отключение/удаление/сохранение правил, отказ валидации без потери правок, пустой список, восстановление defaults, клавиатуру выпадающего списка и запрет преждевременной перезагрузки расширения. Снимок окна просмотрен.
- Сохранение правил использует прежнюю проверку помощника; несохранённые данные не перезаписываются фоновым опросом. Изменённые правила надо сохранить перед закрытием popup.
- Удалены отдельная устаревшая страница маршрутизации и разрешение clipboardRead. Флаги не затемняются; оранжевый акцент остаётся у активного подключения.
- Установочный ZIP прошёл проверку CRC, контрольных сумм, Install.ps1 -VerifyOnly, отказа повреждённому комплекту, framing Native Messaging, допустимого origin и манифестов EXE без повышения прав. Упакованные файлы расширения и README совпадают с исходниками.
- `node --check extension/popup.js` и `git diff --check` прошли. В Git не включаются EXE, ZIP, среды Python, временные профили браузера и снимки макета. Готовый ZIP публикуется отдельно в Releases; его SHA-256 записывается в release.json.

## Границы проверки

Пользовательская подписка и внешние VPN-серверы не проверялись. Полная установка в пользовательский профиль Windows/Chrome не выполнялась, настройки браузера, HKCU и антивируса не изменялись. UI-тест использует имитацию API расширения; локальные интеграционные тесты ядра используют настоящий sing-box.
