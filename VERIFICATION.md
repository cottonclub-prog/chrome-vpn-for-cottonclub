## Проверка 1.6.0 — единое название и папка приложения

5 октября 2026: имя расширения, popup, подсказка Chrome, справка, EXE и ярлыки приведены к `cottonclub vpn for chrome`. Установка, идентификатор устройства и временная конфигурация ядра используют `%LOCALAPPDATA%\cottonclub vpn for chrome`. Помощник устанавливается в постоянную папку `host`; новые каталоги с копиями каждого выпуска не создаются. Подписка и правила остаются в хранилище соответствующего профиля Chrome. Идентификаторы расширений и ключ CRX сохранены.

Установщик переносит прежнюю папку установки и идентификатор без изменения. После регистрации нового помощника удаляются распознаваемые старые каталоги выпусков, перенесённый файл идентификатора и пустые старые каталоги. Посторонние файлы не удаляются. Старые имена присутствуют только в однократной миграции и её тестах; прежнее имя клиента не передаётся серверу подписки. Перед миграцией проверяются пути, ссылки, активный помощник/ядро и корректность идентификатора.

Первый переход выполняется вручную новым EXE или Install.cmd: затем требуется выбрать новую папку расширения без удаления существующей записи. Прежний обновлятор получает архив совместимости и сообщает о необходимости ручного перехода, сохраняя старую установку. После перехода автоматическое обновление использует постоянный новый путь. Удаление сохраняет device-id.txt для переустановки.

Проверки: 51 Python-тест, включая реальный локальный Hysteria 2 и маршрутизацию; 17 Node.js-тестов расширения; popup в отдельном скрытом Chrome; миграция и повторное обновление в изолированных файловых примерах без HKCU; ZIP, контрольные суммы, проверка/отказ повреждённому комплекту, запуск скомпилированного помощника для обоих ID и отказ постороннему; создание идентификатора скомпилированным помощником только в новом каталоге; загрузчик и отчёт об обновлении; EXE --verify-only, asInvoker, подпись CRX3 и XML обновлений. Ограничения: пользовательская установка и реестр не изменялись, подключение к реальному серверу подписки пользователя не проверялось; EXE без Authenticode-подписи.

## Проверка 1.5.0 — CRX и графический EXE

5 октября 2026: собраны подписанный CRX3, updates.xml, SHA256SUMS.txt и самостоятельный EXE с встроенным комплектом. EXE создан из installer/Setup.cs компилятором C# Windows, имеет manifest asInvoker и использует прежний Install.ps1. Прогресс показывает проверку архива, распаковку файлов, проверку payload и установку. Сетевой загрузки во время установки нет. Установщик не правит профили Chrome или корпоративные политики.

Приватный ключ прежнего ID недоступен, поэтому CRX подписан новым локальным ключом и имеет отдельный ID pppgaipmgmbndhejmkabemifkonbgooh. Исходное распакованное расширение сохраняет ID hooimhadihhgfkhidbmjoaojfljafnaf. Новые Native Messaging host и регистрация принимают только эти два ID. Приватный PEM исключён из Git и всех комплектов. Изоляция данных Chrome разных ID описана в README.

Проверено: 47 Python-тестов; 17 Node.js-тестов, включая сохранение VPN при отказе ручного обновления CRX; CRC и контрольные суммы ZIP; проверка/отказ повреждённому установочному комплекту; запуск скомпилированного помощника для обоих ID и отказ постороннему; CRX3 подпись и ID; XML версии/адреса обновления; manifest EXE asInvoker; запуск EXE --verify-only без установки. Окно EXE отрисовано за пределами экрана без запуска установки, снимок просмотрен. Полноценная установка, запись HKCU, корпоративная политика и установка CRX в управляемый Chrome не выполнялись. Authenticode-подписи EXE нет.

Сборка дополнительных файлов: Build-Distribution.ps1 после Build.ps1. Проверка: tests/setup_smoke.py и tests/package_smoke.py.
